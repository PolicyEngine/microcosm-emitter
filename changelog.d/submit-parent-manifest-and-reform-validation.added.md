A `calibration-diagnostics` submission now includes any file handed over with the role `parent_build_manifest` or `reform_validation`, under the same role name, as the collector accepts since PolicyEngine/microcosm-collector#74. A publication copies both at hand-over with its other submitted files, within the same limits, so the build may remove them once the release lands; a hand-over naming neither role is submitted as before. Where emitter releases share one hand-over database: a publication queued by an earlier release and not yet accepted by the collector was copied without the two files, so this release reads them from the build folder, and the whole `calibration-diagnostics` submission stays pending with `PRESERVED_FILES_MISSING` if one was removed, or fails with `PRESERVED_BYTES_CHANGED` if one was rewritten; a submission the collector had already accepted from an earlier release is not sent again, and an earlier release that submits a row this one queued sends it without the two files (microcosm-emitter#97).
