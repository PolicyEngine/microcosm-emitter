The telemetry service no longer retries a settled collector rejection forever. A 4xx other than a timeout (408) or a rate limit (429) on a run's events or registration (an event shape the collector does not accept, say) now makes that run local-only with a recorded reason and one warning. For a refused batch the reason is `collector_rejected_events` and the warning names the status; a refused registration keeps the reason and the warning a 409 already had. Before, the service sent the same request again without end, and the retry delay it set held back every other run it delivers. The rule is about the run and not about who sends it, so a service that has taken over another build's run applies it there too, with no warning in its own build. An expired collector token (401) is still exchanged again, a refused login (403) is handled as before, and a timeout, a rate limit or a server error is still retried. This ports PolicyEngine/microcosm#1147's rule, so both packages' services treat a shared queue's runs alike.
