A telemetry service no longer disables hosted telemetry for other builds that share its queue. Before, a service with no Hugging Face login, or with a login the collector refused, permanently marked every other build's queued run local-only. Now a service touches another build's run only after that build's service has exited, and only one service does so at a time. Each service holds an advisory lock file beside the queue, laid out as Microcosm's telemetry service lays it out from PolicyEngine/microcosm#1177 on, so services from both packages recognise each other's runs. A run with no lock file, from an older service, waits until it has been idle for 15 minutes. A missing, refused or non-owning login decides only the service's own run; another build's run stays pending for a service whose login the collector accepts for it. A refused login is sent to the collector once, not on every pass, and the shutdown drain waits only for the build's own run.
